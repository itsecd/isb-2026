# Отчет по лабораторной работе: Безопасное хранение паролей

## Описание проекта
Приложение представляет собой систему разграничения доступа на базе хэширования паролей с использованием алгоритма Argon2id. В рамках работы реализовано два сценария: безопасный (с уникальной криптографической солью) и уязвимый (без соли / со статической солью).

## Результаты анализа уязвимостей и сравнение
1. **Схема без соли (Небезопасная):** - Уязвима к атакам по словарям и Rainbow Tables (радужным таблицам).
   - Одинаковые пароли разных пользователей (например, `user1` и `user2` с паролем `123`) генерируют абсолютно идентичные хэши в файле `data_base_no_salt.json`. Злоумышленник, получив базу, может взломать всех пользователей одновременно.
2. **Схема с солью (Безопасная):**
   - Для каждого пользователя через `secrets.token_hex(16)` генерируется уникальный криптографический контекст.
   - Даже если пользователи выбирают одинаковые пароли, их хэши в файле `data_base.json` кардинально различаются, делая предварительно вычисленные таблицы взлома бесполезными.
