## Теоретические сведения
**HMAC** (Hash-based Message Authentication Code) — это механизм аутентификации сообщений, основанный на использовании криптографической хеш-функции и секретного ключа. Он был разработан в 1996 году и стандартизирован в RFC 2104.

### Принцип работы HMAC

Алгоритм HMAC работает в два этапа:
**Первый этап (внутренний хеш):**
inner_hash = SHA-256( (K ⊕ ipad) || message )
**Второй этап (внешний хеш):**
HMAC = SHA-256( (K ⊕ opad) || inner_hash )

Где:
- **K** — секретный ключ, дополненный до 64 байт
- **ipad** = 0x36 (повторённый 64 раза)
- **opad** = 0x5C (повторённый 64 раза)
- **⊕** — операция XOR (исключающее ИЛИ)
- **||** — конкатенация (склеивание)

### Свойства HMAC

| Свойство | Описание |
|----------|----------|
| **Целостность** | Изменение сообщения приводит к изменению HMAC |
| **Подлинность** | Только владелец ключа может вычислить правильный HMAC |
| **Лавинный эффект** | Изменение 1 бита входных данных меняет весь хеш |
| **Односторонность** | Из HMAC невозможно восстановить исходное сообщение или ключ |

### Почему используется SHA-256:

- Длина хеша: 256 бит 
- Считается криптостойкой
- Является современным стандартом безопасности

### Тесты 

Какие тесты и что они проверяют
| № | Название теста | Что проверяет | Зачем |
|---|----------------|---------------|-------|
| 1 | `test_compute_hmac_returns_hex` | HMAC возвращает строку из 64 символов | Убедиться, что хеш имеет правильную длину (256 бит = 64 hex-символа) |
| 2 | `test_compute_hmac_different_keys_different_results` | Разные ключи дают разные HMAC | Проверить, что секретный ключ влияет на результат |
| 3 | `test_verify_hmac_correct` | Правильный HMAC успешно проходит проверку | Убедиться, что `verify_hmac()` работает корректно |
| 4 | `test_verify_hmac_incorrect` | Неправильный ключ или изменённое сообщение → проверка не проходит | Проверить, что HMAC отбраковывает подделку |
| 5 | `test_verify_hmac_empty_strings` | Пустые строки обрабатываются корректно | Убедиться в устойчивости к краевым случаям |
