## Теоретические сведения

**Коллизия** хеш-функции — это ситуация, когда для двух различных входных блоков данных генерируется абсолютно одинаковое значение хеша. В криптографии поиск коллизий полной длины (например, полного 256-битного хеша SHA-256) вычислительно невозможен. Для демонстрации механизмов поиска коллизий применяется метод усечения (truncation) хеша до меньшего количества бит.

**Парадокс дней рождения**:
В основе оценки сложности поиска коллизий лежит математический феномен — парадокс дней рождения. В применении к теории вероятностей и криптоанализу он утверждает, что вероятность совпадения значений в выборке растет значительно быстрее, чем кажется на первый взгляд.

Если хеш-функция генерирует N равновероятных значений (где N = 2^b для b-битного усеченного хеша), то математическое ожидание количества случайных генераций до обнаружения первой коллизии рассчитывается по формуле:
E = sqrt( (pi / 2) * 2^b )

Свойства поиска коллизий методом брутфорса:

Метод поиска: Brute-force (полный перебор) с использованием хеш-таблицы (словари в Python) для запоминания встреченных хешей.

Временная сложность: Согласно парадоксу дней рождения составляет O(sqrt(2^b)), что экспоненциально быстрее обычного перебора O(2^b).

Пространственная сложность: Требует сохранения всех сгенерированных ранее значений для проверки дубликатов, что занимает O(sqrt(2^b)) памяти.

Зависимость от разрядности: Увеличение длины усеченного хеша на каждые 2 бита удваивает сложность поиска и время выполнения.

Почему используется SHA-256 с усечением:

SHA-256 гарантирует лавинный эффект: минимальное изменение входной строки полностью меняет результирующий хеш.

Равномерное распределение значений SHA-256 обеспечивает идеальное соответствие практических экспериментов теоретическим расчетам парадокса дней рождения.

## Тесты

### Название теста: test_generate_random_string

- __Что проверяет:__ Соответствие длины сгенерированной строки заданному значению и выброс исключения ValueError при отрицательной длине.

- __Зачем:__ Убедиться, что генератор стабильно создает строки нужной длины и корректно обрабатывает граничные/ошибочные случаи.

### Название теста: test_get_truncated_hash

- __Что проверяет:__ Правильность длины усеченного хеша (8 бит = 2 hex-символа, 12 бит = 3 hex-символа, 16 бит = 4) и генерацию исключения при неразрешенном числе бит.

- __Зачем:__ Гарантировать точность среза хеша в зависимости от разрядности, исключая логические сбои при расчетах.

### Название теста: test_theoretical_attempts

- __Что проверяет:__ Соответствие вычисленного теоретического матожидания формуле парадокса дней рождения.

- __Зачем:__ Подтвердить математическую точность расчетов теории перед сравнением с практическими опытами.

## Инструкция по запуску

**Программа поддерживает два независимых режима работы.**

- Запуск в режиме графического интерфейса (GUI): `python main.py gui`

- Запуск в режиме командной строки (CLI): `python main.py cli --bits 8 --experiments 10 --out results.json`

**Параметры CLI:**
- --bits - разрядность хеша для поиска коллизий (например, 8, 12, 16).
- --experiments - количество независимых запусков для сбора статистики.
- --out - (опционально) путь для сохранения итогового отчета в формате JSON.

#### Запуск юнит-тестов:
- `python -m unittest tests/test_logic.py`
