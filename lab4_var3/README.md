# Отчет по лабораторной работе №4
## Вариант 3: Хеширование паролей и защита учетных данных

Лабораторная работа по реализации системы регистрации и входа пользователей. В проекте сделано два варианта работы: с хэшированием Bcrypt  и демонстрационный на SHA-256 , чтобы показать разницу в защищенности и скорости при попытке подбора паролей.

## Структура проекта

* `main.py` — консольная версия. Парсит аргументы командной строки и запускает нужный режим.
* `gui.py` — графический интерфейс на PyQt6.
* `auth.py` — функции регистрации и входа для режима с Bcrypt.
* `auth_no_salt.py` — функции регистрации и входа для режима с SHA-256.
* `collision.py` — скрипт случайного перебора паролей для консоли с отображением прогресса через `tqdm`.
* `data_processing.py` — чтение и сохранение учетных записей в файлы JSON.
* `unit_test.py` — тесты для проверки хэширования, авторизации и обработки ошибок.
* `settings.json` — конфиг, где прописан путь к базе данных.

## Как работает хэширование

### 1. Bcrypt
* При регистрации пользователя функция `bcrypt.gensalt()` автоматически создает уникальную соль.
* Из-за этого хэши в файле `data.json` всегда разные, даже если у пользователей одинаковые пароли (например, у `user1` и `user2`).

### 2. SHA-256
* Пароль хэшируется напрямую через `hashlib`.
* Если пароли у пользователей одинаковые, то и хэши в файле `data_without_salt.json` будут абсолютно одинаковыми(например, у `user1` и `user2`).

## Запуск проекта
1. Консольная версия запускается через консольнкю комманду: 
python main.py -один_из_пяти_режимов  --user логин --password --путь_к_базе_данных

Режимы для консольной версии:
* `-reg` или `--registration` — регистрация с солью.
* `-aut` или `--authentication` — вход с солью.
* `-reg_nosalt` или `--registration_no_salt` — регистрация без соли.
* `-aut_nosalt` или `--authentication_no_salt` — вход без соли.
* `-dec` или `--decomposition` — запуск подбора пароля.

2. Версия с графическим интерфейсом запускается через команду:
python gui.py
