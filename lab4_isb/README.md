# Отчёт по лабораторной работе №4

## Тема

**Поиск коллизий на укороченных хешах**

## Цель работы

Цель лабораторной работы — разработать программу, которая демонстрирует возникновение коллизий у укороченных хешей, собирает статистику по количеству попыток до нахождения первой коллизии и позволяет сравнить практические результаты с теоретической оценкой, основанной на атаке «дней рождения».

## Задание

Разработать программу, выполняющую:

1. Генерацию случайных строк.
2. Вычисление укороченного хеша.
3. Поиск совпадающих значений.
4. Сбор статистики по количеству попыток.

Программа должна:

1. Автоматически генерировать данные.
2. Выполнять поиск коллизий.
3. Поддерживать длину хеша:
   * 8 бит;
   * 12 бит;
   * 16 бит.
4. Выводить найденные коллизии.

Дополнительно в программе реализованы:

1. Запуск через командную строку с использованием `argparse`.
2. Запуск с параметрами из JSON-файла.
3. Сохранение результатов экспериментов в CSV-файл.
4. Сохранение итоговой статистики в отдельный CSV-файл.
5. Визуализация процесса экспериментов через `tqdm`.
6. Unit-тесты с использованием `pytest`.
7. Графическая обёртка на PyQt6.

## Теоретические сведения

### Криптографическая хеш-функция

Криптографическая хеш-функция — это алгоритм, который преобразует данные произвольной длины в значение фиксированной длины.

В данной работе используется SHA-256. Полный результат SHA-256 имеет длину:

```text
256 бит = 32 байта = 64 hex-символа
```

SHA-256 является детерминированной функцией: один и тот же вход всегда даёт один и тот же хеш. Это свойство позволяет использовать хеш-функции для проверки целостности данных, цифровых подписей, HMAC и других криптографических задач.

Основные свойства криптографической хеш-функции:

1. Детерминированность.
2. Быстрое вычисление.
3. Лавинный эффект.
4. Устойчивость к поиску прообраза.
5. Устойчивость ко второму прообразу.
6. Устойчивость к коллизиям.

В данной лабораторной работе исследуется устойчивость к коллизиям на примере укороченного хеша.

### Hex-представление хеша

В программе хеш SHA-256 представляется в шестнадцатеричном виде.

В hex-записи один символ кодирует 4 бита:

```text
1 hex-символ = 4 бита
```

Поэтому:

```text
8 бит  = 2 hex-символа
12 бит = 3 hex-символа
16 бит = 4 hex-символа
```

Именно поэтому в программе укорочение хеша выполняется через взятие первых `bits // 4` символов hex-строки.

### Укороченный хеш

Укороченный хеш — это часть полного хеша, которая используется вместо всего результата хеш-функции.

В данной работе полный SHA-256 искусственно сокращается до:

```text
8 бит;
12 бит;
16 бит.
```

Это делается не потому, что SHA-256 слабый, а для демонстрации: при использовании слишком короткого хеш-значения количество возможных результатов резко уменьшается, и коллизии становятся легко обнаружимыми.

Количество возможных значений для `n`-битного хеша:

```text
2^n
```

Для используемых длин:

```text
8 бит  → 2^8  = 256 значений
12 бит → 2^12 = 4096 значений
16 бит → 2^16 = 65536 значений
```

### Коллизия

Коллизия — это ситуация, когда два разных входных значения дают одинаковый хеш.

Формально:

```text
m1 ≠ m2
H(m1) = H(m2)
```

В данной работе ищутся коллизии не полного SHA-256, а его укороченного значения.

Пример:

```text
SHA-256(m1) = a3f91c...
SHA-256(m2) = a3f4aa...
```

Для 12-битного хеша оба значения имеют одинаковые первые 3 hex-символа:

```text
a3f = a3f
```

Следовательно, для 12-битного укороченного хеша это коллизия.

### Почему коллизии неизбежны

Коллизии неизбежны, потому что хеш-функция отображает большое количество возможных входных данных в ограниченное количество выходных значений.

Это объясняется принципом Дирихле: если объектов больше, чем ячеек, то хотя бы в одной ячейке окажется больше одного объекта.

В контексте хеширования:

```text
объекты — входные строки;
ячейки — возможные значения хеша.
```

Например, для 8-битного хеша существует всего 256 возможных значений. Если сгенерировать больше 256 разных строк, то минимум две из них обязательно дадут одинаковый 8-битный хеш.

Для полного SHA-256 коллизии тоже математически существуют, но их поиск практически невозможен из-за огромного пространства значений:

```text
2^256
```

### Атака «дней рождения»

Атака «дней рождения» основана на парадоксе дней рождения.

Парадокс заключается в том, что в группе из 23 человек вероятность совпадения дней рождения у двух людей уже превышает 50%, хотя в году 365 дней. Это происходит потому, что сравнивается не один человек с одним днём, а все пары людей между собой.

Аналогично работает поиск коллизий хеш-функции.

Если длина хеша равна `n` бит, то всего существует:

```text
2^n
```

возможных значений. Однако коллизию обычно можно найти не за `2^n`, а примерно за:

```text
2^(n/2)
```

попыток.

Для длин из лабораторной работы:

```text
8 бит  → около 2^4 = 16 попыток
12 бит → около 2^6 = 64 попытки
16 бит → около 2^8 = 256 попыток
```

Это не точное количество для каждого запуска, а теоретическая оценка порядка роста. Поэтому в программе выполняется серия экспериментов, после чего рассчитывается среднее количество попыток.

### Почему увеличение длины хеша повышает безопасность

При увеличении длины хеша растёт количество возможных значений.

Если длина хеша увеличивается с 8 до 16 бит, то число возможных значений растёт с:

```text
2^8 = 256
```

до:

```text
2^16 = 65536
```

Чем больше пространство хеш-значений, тем меньше вероятность случайного совпадения и тем сложнее найти коллизию.

Для поиска коллизий сложность оценивается примерно как:

```text
2^(n/2)
```

Поэтому для полного SHA-256 стойкость к коллизиям оценивается примерно как:

```text
2^128
```

что практически недостижимо для перебора.

### Почему MD5 считается небезопасным

MD5 считается небезопасным, потому что для него существуют практические атаки на коллизии.

MD5 выдаёт 128-битный хеш. Для идеальной 128-битной хеш-функции стойкость к коллизиям должна быть около:

```text
2^64
```

операций. Однако у MD5 обнаружены криптографические слабости во внутренней структуре, из-за которых коллизии можно находить значительно быстрее.

Из-за этого MD5 нельзя использовать для задач, где требуется криптографическая безопасность:

1. Цифровые подписи.
2. Сертификаты.
3. Проверка подлинности данных.
4. Хранение паролей.
5. Аутентификация сообщений.

В современных системах вместо MD5 используют более стойкие алгоритмы:

```text
SHA-256;
SHA-384;
SHA-512;
SHA-3.
```

## Описание алгоритма

Общий алгоритм поиска коллизии:

1. Создать пустой словарь для хранения уже встреченных укороченных хешей.
2. Сгенерировать случайную строку.
3. Вычислить SHA-256 от этой строки.
4. Укоротить хеш до 8, 12 или 16 бит.
5. Проверить, встречался ли такой укороченный хеш ранее.
6. Если не встречался — сохранить пару:

```text
укороченный_хеш → строка
```

7. Если встречался — сравнить старую строку и новую.
8. Если строки разные, зафиксировать коллизию.
9. Записать результат в CSV-файл.
10. Повторить эксперимент заданное количество раз.
11. Рассчитать статистику.

Словарь используется для быстрого поиска уже встреченных значений:

```text
{
    "a3": "Qwe123Ab",
    "7f": "Test889X",
    "00": "Lm901Zxc"
}
```

Если новая строка даёт уже существующий укороченный хеш, программа проверяет, что строки различаются. Если строки разные, значит найдена коллизия.

## Описание основных функций

### `generate_random_string(length)`

Генерирует случайную строку заданной длины из латинских букв и цифр.

Используется для автоматической генерации входных данных.

### `hash_string(string)`

Вычисляет SHA-256 от строки и возвращает результат в hex-виде.

### `cut_hash(hashed_string, bits)`

Укорачивает hex-представление хеша до заданного числа бит.

Поддерживаемые значения:

```text
8;
12;
16.
```

Так как один hex-символ равен 4 битам, функция берёт первые `bits // 4` символов.

### `find_collision(length, bits)`

Ищет первую коллизию для укороченного хеша.

Функция возвращает словарь:

```text
hash     — совпавший укороченный хеш;
string1  — первая строка;
string2  — вторая строка;
attempts — количество попыток до нахождения коллизии.
```

### `experiment(length, bits, num_experiments, file_name)`

Запускает серию экспериментов для одной длины хеша.

Для каждого эксперимента:

1. Ищется первая коллизия.
2. Записывается номер эксперимента.
3. Записывается длина хеша.
4. Результат сохраняется в CSV.

Для отображения прогресса используется `tqdm`.

### `stats_from_csv(filename)`

Считывает результаты экспериментов из CSV-файла и рассчитывает статистику:

```text
количество экспериментов;
среднее число попыток;
минимальное число попыток;
максимальное число попыток;
теоретическую оценку 2^(bits/2).
```

### `stats_to_csv(filename, stats)`

Сохраняет рассчитанную статистику в отдельный CSV-файл.

## Формат выходных файлов

### Файл `collisions.csv`

Файл содержит найденные коллизии.

Поля:


Пример:


## Анализ результатов

В ходе экспериментов ожидается, что среднее количество попыток будет увеличиваться при росте длины укороченного хеша.

Теоретическая оценка:

```text
8 бит  → 2^(8/2)  = 16
12 бит → 2^(12/2) = 64
16 бит → 2^(16/2) = 256
```

Практические значения могут отличаться, потому что поиск коллизий является вероятностным процессом. Однако общий порядок роста должен сохраняться:

```text
для 8 бит попыток меньше всего;
для 12 бит больше;
для 16 бит ещё больше.
```

Если экспериментальные средние значения растут при увеличении длины хеша, это подтверждает теоретическую зависимость.

## Ответы на контрольные вопросы

### Что такое коллизия?

Коллизия — это ситуация, когда два разных сообщения дают одинаковый хеш. В данной работе рассматривается коллизия укороченного SHA-256, когда совпадают только первые 8, 12 или 16 бит полного хеша.

### Почему коллизии неизбежны?

Коллизии неизбежны, потому что количество возможных входных данных больше количества возможных хеш-значений. Если разных входов больше, чем выходов, то некоторые разные входы обязательно попадут в одно и то же значение хеша.

### Что такое атака «дней рождения»?

Атака «дней рождения» — это способ поиска коллизий, основанный на том, что совпадение среди пар объектов появляется быстрее, чем кажется интуитивно. Для `n`-битного хеша коллизию обычно можно найти примерно за `2^(n/2)` попыток.

### Почему увеличение длины хеша повышает безопасность?

Увеличение длины хеша увеличивает количество возможных хеш-значений. Из-за этого снижается вероятность случайного совпадения и растёт количество попыток, необходимых для нахождения коллизии.

### Почему MD5 считается небезопасным?

MD5 считается небезопасным, потому что для него существуют практические атаки на коллизии. Это значит, что можно подобрать два разных сообщения с одинаковым MD5-хешем. Поэтому MD5 нельзя использовать в криптографически значимых задачах.

Программа автоматически генерирует случайные строки, вычисляет SHA-256, укорачивает хеш до 8, 12 или 16 бит и ищет две разные строки с одинаковым укороченным хешем.

Результаты экспериментов сохраняются в CSV-файл, после чего рассчитывается статистика по количеству попыток. Полученные данные позволяют сравнить практические результаты с теоретической оценкой `2^(n/2)`, основанной на атаке «дней рождения».

Работа показывает, что при уменьшении длины хеша вероятность коллизии резко возрастает. Даже если используется стойкая хеш-функция SHA-256, искусственное сокращение её результата до малого числа бит делает поиск коллизий практически выполнимым.

Таким образом, безопасность хеш-функции зависит не только от выбранного алгоритма, но и от длины используемого хеш-значения.
